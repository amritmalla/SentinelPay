# risk-model

Synthetic fraud scoring for SentinelPay — the **ML engineering lifecycle**, not a claim of real-world fraud efficacy.

```text
data → features → train → evaluate → calibrate → serve → explain → drift
```

The model is trained on *synthetic* transactions generated by `riskmodel.datagen`. It learns the generator’s fraud archetypes (velocity burst, card testing, amount outlier, geo mismatch, night owl). Reviewers should treat metrics as proof of pipeline discipline, not detection power on live card traffic.

## Layout

| Path | Role |
| --- | --- |
| `src/riskmodel/datagen/` | Seeded synthetic generator (parquet + dataset hash) |
| `src/riskmodel/features/` | Shared feature builder (train == serve) |
| `src/riskmodel/train/` | Train / calibrate / evaluate |
| `src/riskmodel/serve/` | FastAPI `/score`, `/healthz`, `/metrics`, `/model-info` |
| `models/` | Committed LightGBM artifact + `metadata.json` |
| `reports/` | Evaluation report + plots |

## Tooling

```bash
cd risk-model

```

## Honesty rule

Never market this as production fraud detection. The deliverable is calibrated serving, SHAP factors, versioning (`ml-v…+<hash>`), and safe fallback when the model is unavailable.
